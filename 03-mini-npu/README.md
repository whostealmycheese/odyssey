# 🧠 Mini NPU Simulator: AI 가속기 MAC 연산 시뮬레이터

AI/딥러닝 하드웨어 가속기(NPU)의 핵심 연산인 **MAC(Multiply-Accumulate, 곱셈-누적) 연산**을 Python 순수 반복문으로 직접 구현하고, 크기별 패턴 인식 판정 및 $O(N^2)$ 성능 특성을 분석하는 프로젝트입니다.

---

## 1. 프로젝트 개요
- **목표:**
  - 시각적 패턴(십자가, X)을 2차원 숫자 행렬로 변환하여 필터와 대조하는 AI 연산의 원리 습득
  - 외부 라이브러리(NumPy 등) 없이 순수 2중 반복문으로 2차원 MAC 연산기 구현
  - 비정형 라벨(`+`, `x`, `cross`)의 표준화(`Cross`, `X`) 및 부동소수점 오차 방어(`epsilon=1e-9`)
  - 패턴 크기($3 \times 3 \sim 25 \times 25$) 증가에 따른 연산 시간 실측 및 $O(N^2)$ 시간 복잡도 검증
  - [보너스] 1차원 평탄화(Flattened) 메모리 접근 최적화 및 $N \times N$ 패턴 자동 생성기 탑재

## 3. 핵심 구현 요약

### 1) 순수 2차원 MAC(Multiply-Accumulate) 연산 (`mac_engine.py`)
```python
def compute_mac(pattern: List[List[float]], filter_mat: List[List[float]]) -> float:
    score = 0.0
    for r in range(len(pattern)):
        for c in range(len(pattern[0])):
            score += float(pattern[r][c]) * float(filter_mat[r][c])
    return score
```
* 두 $N \times N$ 2차원 행렬의 동일한 좌표 원소를 곱하고 누적 합산합니다.
* 특정 패턴이 필터와 형태상 일치할수록 높은 점수를 산출합니다.

### 2) 라벨 표준화(정규화) 정책 (`data_loader.py`)
* `data.json` 내의 비정형 라벨 표기를 내부 표준 라벨 2가지로 통일:
  - `'+'` 및 `'cross'` ➔ **`'Cross'`**
  - `'x'` 및 `'times'`  ➔ **`'X'`**
* 모든 콘솔 출력, 판정, 비교 검증은 표준 라벨(`Cross`, `X`)을 기준으로 일관되게 수행됩니다.

### 3) 부동소수점 허용오차(Epsilon = `1e-9`) 기반 비교 정책
* 컴퓨터의 2진수 부동소수점 연산 특성상, 수학적으로 동일한 값이라도 IEEE 754 반올림 오차가 발생합니다 (예: $0.9 - 0.9 = 1.11 \times 10^{-16}$).
* 단순 등호(`==`) 비교 대신 허용오차 기준을 엄격히 적용:
  $$\text{diff} = |Score_{\text{Cross}} - Score_{\text{X}}|$$
  - $\text{diff} < 10^{-9}$ 일 경우 ➔ **`UNDECIDED` (동점 / 판정 불가)**
  - $\text{diff} \ge 10^{-9}$ 일 경우 ➔ 더 높은 점수를 획득한 라벨 판정

### 2) 결과 리포트: 실패 원인 분석 (Failure Analysis)

본 프로젝트의 `data.json` 데이터셋 분석 결과, 총 6건 중 3건(PASS)과 3건(FAIL)이 발생하였습니다. 실패 케이스를 시스템의 3단계(데이터/스키마 vs 알고리즘 로직 vs 수치 비교 정책) 관점에서 체계적으로 분석한 결과는 다음과 같습니다:

1. **실패 케이스 식별:**
   * `size_5_1`: Cross 점수 $0.9000000000000000$ vs X 점수 $0.8999999999999999$ ($\text{diff} \approx 1.11 \times 10^{-16}$)
   * `size_13_2`: Cross 점수 $7.4999999999999973$ vs X 점수 $7.5000000000000000$ ($\text{diff} \approx 2.66 \times 10^{-15}$)
   * `size_25_1`: Cross 점수 $4.9000000000000004$ vs X 점수 $4.8999999999999986$ ($\text{diff} \approx 1.78 \times 10^{-15}$)
2. **원인 1 - 수치 비교 정책(Epsilon Tie-breaking):**
   * 과제 명세서의 필수 규칙인 `abs(score_a - score_b) < 1e-9` 정책에 따라, 위 3건은 두 점수의 차이가 $10^{-15} \sim 10^{-16}$ 수준으로 허용오차 $10^{-9}$보다 훨씬 작습니다.
   * 따라서 모델은 두 점수를 수학적 오차 범위 내의 동점으로 판별하여 정상적으로 **`UNDECIDED` (판정 불가)** 결론을 내렸습니다.
   * 하지만 `expected` 정답 라벨은 각각 `'x'` 또는 `'+'`로 지정되어 있었기 때문에 `UNDECIDED != expected` 불일치가 발생하여 최종 판정이 `FAIL`로 처리되었습니다.
3. **원인 2 - 필터 가중치 설계(Data Bias):**
   * 실패한 입력 패턴들은 교차점(중앙)이나 특정 축에 필터 가중치가 의도적으로 분산 배치되어 있어, 십자가 필터와 X 필터 양쪽 모두에서 동일한 유효 합산값을 산출하도록 설계된 대칭적 데이터셋입니다.
4. **결론 및 개선 대책:**
   * 이번 실패는 프로그램 코드의 버그나 연산 로직 오류가 아니라, **"부동소수점 오차에 따른 동점 판정 정책(Epsilon Policy)이 완벽하게 작동한 결과"**입니다.
   * 실무 환경에서는 1) 필터의 가중치를 정규화(L2 Normalization)하거나, 2) 소프트맥스(Softmax) 확률 분포 및 Confidence 임계값(Threshold)을 도입하여 동점 영역을 줄이거나, 3) 0이 아닌 유의미한 마진(Margin)을 두어 판정 신뢰도를 높이는 정책으로 고도화할 수 있습니다.

### 3) 성능 분석 및 시간 복잡도 $O(N^2)$ 해석

#### 크기별 순수 MAC 연산 시간 실측표 (10회 반복 측정 평균)

| 패턴 크기 ($N \times N$) | 연산 횟수 ($N^2$) | 평균 연산 시간 (ms) | 이론적 연산 배율 (기준: $3 \times 3$) | 실측 시간 배율 |
| :---: | :---: | :---: | :---: | :---: |
| **$3 \times 3$** | 9 회 | **0.0006 ms** | 1.0 배 | 1.0 배 |
| **$5 \times 5$** | 25 회 | **0.0010 ms** | 2.8 배 | 약 1.7 배 |
| **$13 \times 13$** | 169 회 | **0.0056 ms** | 18.8 배 | 약 9.3 배 |
| **$25 \times 25$** | 625 회 | **0.0202 ms** | 69.4 배 | 약 33.7 배 |

#### 시간 복잡도 $O(N^2)$ 분석 및 하드웨어적 고찰:
1. **$O(N^2)$ 복잡도의 수학적 근거:**
   * 2차원 행렬의 가로와 세로 길이가 모두 $N$이므로, $N$개의 행(Row)을 순회하면서 각 행마다 $N$개의 열(Column)에 대해 곱셈과 누적 덧셈을 수행합니다.
   * 총 연산 횟수는 정확히 $N \times N = N^2$번 발생하므로, 시간 복잡도는 엄밀하게 **$O(N^2)$**를 따릅니다.
2. **연산량 폭증의 이유:**
   * $3 \times 3$의 경우 9번의 MAC 연산에 불과하지만, 크기가 불과 8배 증가한 $25 \times 25$에서는 연산량이 $625$번으로 **약 70배 폭증**합니다.
   * 고해상도 이미지($1024 \times 1024$)나 딥러닝 레이어(수백 채널)에서는 연산량이 수억~수조 단위로 치솟게 됩니다.
3. **NPU(Neural Processing Unit)가 필요한 이유:**
   * 일반 CPU는 2중 for 루프를 통해 데이터를 순차적으로(Sequential) 하나씩 곱하고 더하므로, $N$이 커질수록 레이턴시가 급격히 늘어납니다.
   * 반면 NPU는 시스톨릭 어레이(Systolic Array)나 대규모 병렬 곱셈기(PE, Processing Element)를 칩 내부에 집적하여, $N^2$번의 곱셈-누적 연산을 **단 1 클록(Clock Cycle)에 동시 병렬 처리**함으로써 전력 효율과 처리 속도를 수백 배 혁신합니다.

## 5. 보너스 과제 구현 결과

### 1) 1차원 평탄화(Flattened) 메모리 접근 최적화
2차원 중첩 리스트(`mat[r][c]`)는 포인터를 2번 역참조(Double Dereferencing)하여 캐시 로컬리티가 떨어집니다. 이를 1차원 연속 배열(`arr[i]`)로 평탄화하여 단일 루프로 실행했을 때의 벤치마크 결과입니다:

```text
#---------------------------------------
# [보너스] 1차원 메모리 접근 최적화 벤치마크 (25x25, 100회 반복)
#---------------------------------------
기존 2차원 중첩 루프 평균 연산 시간: 0.0181 ms
최적화 1차원 단일 루프 평균 연산 시간: 0.0084 ms
💡 메모리 인덱싱 접근 최적화 속도 향상: +53.6%
```
* **결과:** 2차원 인덱싱 오버헤드를 줄인 것만으로 **약 53.6%의 연산 속도 개선**을 달성하였습니다.

### 2) $N \times N$ 패턴 자동 생성기 (`generate_pattern`)
임의의 크기 $N$을 입력받아 대칭적인 십자가(Cross) 및 X 패턴을 자동으로 생성할 수 있는 유틸리티를 구현하여, 향후 임의의 대형 행렬 테스트에 재활용 가능하도록 모듈화하였습니다.

## 7. 핵심 개념 정리 (FAQ)

### Q1. MAC(Multiply-Accumulate) 연산이란 무엇인가요?
입력값과 가중치를 곱하고(Multiply), 이전 결과에 지속해서 누적 합산(Accumulate)하는 연산($\text{Score} = \sum P_i \cdot W_i$)으로, 합성곱 신경망(CNN) 및 행렬 곱셈의 99%를 차지하는 핵심 연산입니다.

### Q2. 왜 '부동소수점 오차(Epsilon)' 정책이 필수적인가요?
컴퓨터는 실수를 2진수 비트로 표현하므로 $0.1 + 0.2 = 0.30000000000000004$와 같은 미세 오차가 발생합니다. 만약 단순 등호(`==`)를 사용하면 동점이어야 할 케이스가 $10^{-16}$ 차이로 엉뚱한 승자가 결정되므로, $10^{-9}$ 이하의 차이는 동점(`UNDECIDED`)으로 수렴시키는 비교 정책이 필수적입니다.

### Q3. 라벨 정규화(Normalization)가 필요한 이유는 무엇인가요?
외부 데이터셋마다 정답이나 키를 `+`, `cross`, `x`, `X` 등 제각각으로 표기할 수 있습니다. 비즈니스 로직에 들어가기 전 하나의 표준 라벨(`Cross`, `X`)로 통일해야 조건문 분기가 단순해지고 비교 누락 오류를 원천 차단할 수 있습니다.
